# 命题对齐说明

## 官方命题

**如果你加入赛力斯超级工厂团队，你如何打造一名会主动管控设备质量风险的 AI数字员工？**

官方说明关注：基于本体论和知识图谱建设设备—质量知识底座，探索 Graph RAG、Autonomous Agent 等方式主动捕捉异常、调用知识与工具链研判、输出可解释证据链和处置方案，并结合飞书 Aily、多维表格实现从感知到行动的协同闭环。

本仓库对齐该方向，但严格区分“已实现的比赛原型底座”和“必须在企业环境验证的目标能力”。

## 官方要点逐项对齐

| 官方命题要点 | 当前可核验实现 | 尚未完成或不能声称 |
|---|---|---|
| 本体论与知识图谱 | 设备、工位、程序、紧固点、质量特性、失效模式、原因、验证动作和责任角色的节点与关系 | 合成条目，不是企业正式本体；没有真实数据权限和版本治理 |
| 主动捕捉异常 | 离线事件重放自动触发 SPC、设备信号和风险分析；不是等待聊天提问 | 未接实时消息总线、设备流或企业告警平台 |
| Graph RAG | 从异常对象检索有限关系子图，并把 PFMEA、控制计划、报警字典和历史案例作为证据 | 只是 Graph Retrieval + 确定性研判；未发生真实 Graph RAG/LLM 调用 |
| Autonomous Agent | [`DigitalEmployee`](../src/torque_guard/agent.py) 执行真实操作，AuditTrail 记录调用边界和失败 | 不是任意自治；没有自主停线、改参数、确认根因或生产环境长循环 |
| 深度研判 | 结构化研判器要求结论/候选原因引用已知证据，证据不足拒答；外部模型接口有 Schema 与安全回退 | 默认结果来自确定性研判；外部接口存在不等于已使用大模型 |
| 可解释证据链 | 每条证据包含 ID、类别、观察、来源、定位、强度和数据；推断引用证据 ID | 企业接入后仍需文档版本、权限、保留策略和防篡改日志 |
| 处置方案 | 候选原因、验证步骤、责任角色、时限、审批要求和验收依据 | 只是待验证草案，不是已确认根因或真实现场处置 |
| 人工门禁 | 状态机阻止审批前建任务、无证据验证通过和无说明结案 | 当前状态机在本地内存/产物中，未接企业身份、审批或持久化 |
| 飞书多维表格 | 默认生成本地预览；live 客户端能鉴权并向风险/任务表批量写入 | 测试使用假传输；没有授权租户 record ID、截图或调用日志 |
| 飞书 Aily | 已定义企业试点中的受控工具方向 | 未创建或验证真实 Aily 应用，不能作为“已使用飞书 AI 能力”证据 |
| 从感知到行动 | 仓库覆盖感知、检测、检索、结构化研判、审批状态和任务载荷的数据合同 | 没有完成真实人员处理、验证、结案和知识回写的企业闭环 |

## 评测口径

仓库提供两套不能合并的合成验证：

1. **P03 主演示序列：**49 个高度重叠滚动窗口，召回率 94.4%、精确率 94.4%、误报率 3.2%；
2. **多场景独立合成套件：**正常、规格内漂移、传感器零漂、重复报警各 30 例。三类异常召回率 100%（95% Wilson 区间 95.91%–100%），正常误报率 0%（区间 0%–11.35%），预设原因 Top-1 100%。

第二套中的传统报警代理召回率为 66.67%，但代理只检查已有报警码或非 `OK` 结果，不代表赛力斯现有系统。两套结果都不能外推到真实工厂，也不能证明平均提前 2 小时、定位时间缩短 30% 或企业降本收益。详细说明见 [`evaluation.md`](evaluation.md) 和 [`business-value.md`](business-value.md)。

## “自主”的约束定义

本项目把“自主”限定为：在给定事件中发起分析、调用受控工具、保存真实调用记录、在证据范围内组织待验证假设，并推进合法的工作流状态。停线、参数修改、批次隔离、产品放行、根因确认和结案都由授权人员决定。

这一定义既保留 Agent 的主动性，也避免把比赛原型描述成已上线的无人监督生产控制系统。
