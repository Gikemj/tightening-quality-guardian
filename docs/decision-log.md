# 方案决策记录

## ADR-001：先做一个拧紧工位

**决定：**MVP 聚焦一个模拟总装关键拧紧工位，P03 作为端到端主演示对象。

**理由：**设备参数与产品质量关系明确，能够同时验证 SPC、设备信号、PFMEA、知识关系、研判和任务合同。若同时覆盖冲压、焊装、涂装和总装，只能停留在概念层。

**边界：**场景编号和数据均为合成内容；其他工序不能直接复用拧紧阈值。

## ADR-002：风险是候选结论，不是自动根因

**决定：**输出候选原因、置信度、证据 ID 和现场验证方法，根因由工程师确认。

**理由：**设备、材料、工艺和量测信号可能相关，但现场因果需要额外检查。历史案例和模型输出都不能单独确认根因。

**实现：**结构化研判要求每条支持性结论和候选原因引用已存在的 `evidence_id`；证据不足时拒答。

## ADR-003：默认确定性推理，外部模型显式可选

**决定：**公开演示默认使用透明规则、有限图检索和确定性研判器。保留可注入的外部模型接口，但不默认启用。

**理由：**评委可以复现每个数字和来源；没有密钥或外部服务时仍能安全运行。外部输出必须通过 JSON Schema、证据引用和越权断言校验，失败时回退到确定性研判。

**边界：**仓库没有真实模型 SDK、生产密钥或成功外部调用证据。接口存在不能表述为本项目已使用 LLM，也不能把当前关系检索称为完整 Graph RAG。

## ADR-004：飞书默认预览，live 必须显式授权

**决定：**公开演示和 CLI 默认生成本地字段预览；同时提供显式 `live` 模式的多维表格客户端。

**理由：**预览模式便于安全复现；企业试点又需要验证真实鉴权与写入路径。live 模式必须同时具备完整环境配置，以及与风险卡工作流中具名批准事件一致的批准凭证、批准人和批准依据，否则失败关闭。

**边界：**自动化测试只使用假传输验证请求结构。仓库没有授权企业租户调用证据，没有接入飞书审批、企业用户目录或 Aily，也没有完成结案/案例表写回。因此不能声称已形成真实飞书闭环。

## ADR-005：审计轨迹来自真实调用边界

**决定：**不再使用预先写好的五步轨迹作为 Agent 证明；所有轨迹由 `AuditTrail.invoke` 在实际操作边界产生。

**理由：**固定文字无法证明工具是否真正执行，也无法记录失败。真实边界记录包含调用 ID、时间、耗时、输入/输出摘要、成功/失败和错误。

**边界：**当前记录随风险卡保存为 JSON，尚不是具备持久化、访问控制、签名或防篡改能力的企业审计平台。

## ADR-006：审批与结案使用显式状态机

**决定：**用 `RiskCaseWorkflow` 表达待审批、批准/驳回、建任务、验证、结案和重开，拒绝非法越级。

**理由：**“生成了任务字段”不等于业务闭环。状态机可以明确谁做了什么、需要哪些说明和证据，并为未来飞书/工单集成提供稳定合同。

**边界：**完整状态路径由单元测试验证；preview 与网页只展示初始化快照。live CLI 已按“本地批准→外部写入成功→任务已创建”协调状态，部分失败会停在已批准，但这些测试使用假传输，仍未记录真实工程师处理、企业审批或结案。

## ADR-007：用两套合成评测回答不同问题

**决定：**保留 P03 的 49 个重叠窗口用于连续回放，另建 120 个独立合成案例用于多场景分支和原因排序验证，不合并两套指标。

**理由：**滚动窗口贴近时序演示，但相邻样本高度相关；独立生成案例更适合检查场景覆盖。两者结合能更清楚地暴露代码行为。

**边界：**独立案例仍由预设生成器产生，100% 召回或原因命中不能外推；传统报警对照只是透明代理，不代表企业现有系统。

## ADR-008：企业价值只通过对照试点确认

**决定：**仓库只报告合成原型指标和试点目标，不预写企业 ROI 或降本金额。

**理由：**真实收益需要企业事件量、成本、Before/After 时间戳和归因评审。计划采用 2–4 周静默观察与 4 周受控对照。

**边界：**高风险召回率 ≥85%、误报率 ≤15%、平均提前 ≥2 小时和定位时间缩短 ≥30% 都是待验证目标，不是已实现成绩。
