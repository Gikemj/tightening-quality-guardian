# 离线验证说明

## 验证目标

仓库提供两套用途不同的合成验证：

1. **主演示序列滚动窗口：**验证 P03“规格内缓慢漂移”能否沿时间重放，并生成可追溯风险卡和完整任务字段；
2. **多场景独立合成套件：**验证正常、规格内漂移、传感器零漂和重复报警的代码路径、证据与预设首要原因排序。

它们只回答“仓库内预设行为能否复现”，不证明真实工厂泛化、真实根因准确率、飞书/Aily 企业闭环或业务收益。两套样本结构不同，不能合并计算。

## A. 主演示序列：49 个重叠滚动窗口

### 数据与标签

[`generate_demo_data.py`](../scripts/generate_demo_data.py) 使用固定随机种子 `20260717`，生成 820 条记录。P03 最后 36 条被标为 `hidden_risk`，注入扭矩缓慢上移、角度离散增大、重试增加、电流和节拍轻微变化。扭矩仍控制在 43–53 N·m 规格内。

验证从第 124 条 P03 记录开始，每隔 2 条形成一个滚动样本，共 49 个窗口。最近 24 条中含 `hidden_risk` 即为正样本；风险等级为中或高视为系统提示。

相邻窗口共享大部分记录，因此 49 是窗口数，不是 49 个独立故障案例，也不能据此计算企业事件成功率。

### 结果

混淆矩阵：TP=17、FP=1、TN=30、FN=1。

| 指标 | 结果 | 计算 | 边界 |
|---|---:|---|---|
| 召回率 | 94.4% | `TP/(TP+FN)=17/18` | 合成异常窗口被提示的比例 |
| 精确率 | 94.4% | `TP/(TP+FP)=17/18` | 提示窗口中含合成异常的比例 |
| 误报率 | 3.2% | `FP/(FP+TN)=1/31` | 合成正常窗口被提示的比例 |
| 证据可追溯率 | 100% | 同时有来源和定位的证据/全部证据 | 只证明字段结构，不证明结论正确 |
| 任务字段完整率 | 100% | 同时有责任角色、时限和验收依据的任务/全部任务 | 只证明草案结构，不证明真实任务执行 |

原始指标见 [`outputs/metrics.json`](../outputs/metrics.json)。

## B. 多场景套件：120 个独立合成案例

### 生成方式

[`scenarios.py`](../src/torque_guard/scenarios.py) 为四类场景各生成 30 个带独立随机种子的合成案例：

| 场景 | 真值 | 预设验证重点 |
|---|---|---|
| `normal` | 正常 | 不应产生中/高风险 |
| `hidden_torque_drift` | 异常 | 规格内扭矩中心及设备侧信号变化 |
| `sensor_zero_drift` | 异常 | 零点/测量可信度相关报警与证据 |
| `repeated_alarm` | 异常 | 重复报警和历史/报警字典证据 |

这些案例彼此独立生成，但仍由已知规则和标签共同设计，难度远低于未知现场数据。

### 结果

混淆矩阵：TP=90、FP=0、TN=30、FN=0。

| 指标 | 结果 | 95% Wilson 区间 | 准确含义 |
|---|---:|---:|---|
| 三类异常召回率 | 100%（90/90） | 95.91%–100% | 三类预设异常均进入中/高风险 |
| 正常误报率 | 0%（0/30） | 0%–11.35% | 30 个预设正常案例未提示；不能宣称真实误报率为 0 |
| 预设首要原因 Top-1 命中率 | 100%（90/90） | 未报告 | 命中生成器预设标签，不是现场根因诊断准确率 |
| 传统报警代理召回率 | 66.67%（60/90） | 未报告 | 代理只检查最近窗口是否已有报警码或非 `OK` 结果 |
| 传统报警代理误报率 | 0%（0/30） | 未报告 | 不是企业报警平台实测值 |

传统报警代理是公开、可解释的代码对照，不代表赛力斯或任何企业当前系统。100% 结果主要证明预设生成器、检测规则、知识证据与原因标签之间的一致性。

原始指标见 [`outputs/scenario_metrics.json`](../outputs/scenario_metrics.json)，计算见 [`evaluate_scenarios.py`](../scripts/evaluate_scenarios.py)。

## Agent、工作流与飞书测试验证了什么

- Agent 测试证明工具轨迹在真实 Python 调用边界产生，并会记录失败；
- 研判测试证明支持性结论引用已知 `evidence_id`、证据不足拒答、危险外部输出会回退；
- 工作流测试证明审批前不能建任务、验证通过需要证据、结案需要说明；
- 飞书 live 测试通过注入式假传输验证鉴权与风险/任务表请求结构。

上述都是代码级测试。假传输没有访问飞书网络；工作流没有记录真实工程师操作；外部模型接口测试没有证明本项目演示发生过真实 LLM 调用。

## 如何复现

在已经执行 `python -m pip install -e .` 的 Python 3.10+ 环境中：

```powershell
python scripts/generate_demo_data.py
python scripts/build_demo_assets.py
python scripts/evaluate.py
python scripts/evaluate_scenarios.py
python -m unittest discover -s tests -v
node --test tests/web-engine.test.mjs
python scripts/audit_repository.py
```

主序列结果写入 `outputs/metrics.json`，多场景结果写入 `outputs/scenario_metrics.json`。构建脚本同步网页权威风险卡与基线卡；审计检查 Python/网页口径、证据、人工门禁、页面结构和敏感信息。

## 共同限制

- 所有量测、标签、报警、设备、工位、知识和案例均为比赛合成内容；
- 只有一个模拟工具、车型和程序，没有真实现场分布或跨域验证；
- 传感器零漂和重复报警虽有独立合成覆盖，但不是实体传感器故障试验；
- 尚未覆盖维修后基线重建、长期季节性变化、真实换型、数据延迟和概念漂移；
- 阈值按合成场景设定，未按企业误报、漏报和停线成本校准；
- 尚未进行工程师盲测、真实飞书/Aily 租户联调、外部模型线上评测或安全红队；
- 没有真实缺陷确认、停线、工程介入和财务数据，不能计算提前量、定位效率或 ROI。

进入企业阶段应按 [`pilot-plan.md`](pilot-plan.md) 先执行 2–4 周静默观察，再执行 4 周受控对照；业务价值统一按 [`business-value.md`](business-value.md) 的口径计算。
