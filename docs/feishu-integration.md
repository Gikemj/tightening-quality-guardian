# 飞书协同接入设计

## 目标

发现风险后，系统先创建一条风险主记录，再把需要核实的点检、抽检或追溯动作拆成任务，写明责任角色和时限。工程师回写结果后才进入结案。

## 多维表格建议

### 风险主表

风险卡编号、工位、工具、紧固点、风险等级、动态指数、窗口开始/结束、证据数量、当前状态、审批人、结案时间。

### 任务子表

任务编号、风险卡编号、任务内容、责任角色、责任人、时限、审批要求、验收依据、状态、附件、处理结论。

### 知识案例表

失效模式、最终原因、验证方法、处置措施、效果验证、适用范围、来源风险卡、版本和批准人。

## Aily / Agent 工具

建议向 Agent 暴露受控工具，而不是任意调用接口：

1. `read_recent_events`：按授权对象读取最近窗口；
2. `run_spc_checks`：返回规则命中和计算细节；
3. `retrieve_quality_subgraph`：返回有来源的子图；
4. `create_risk_draft`：生成草案，不直接发布；
5. `create_tasks_after_approval`：审批后写入多维表格；
6. `close_case`：核对验收字段后结案并沉淀案例。

## 权限

读权限按工厂、车间和数据域控制。写权限只开放给风险和任务表，不开放 PLC 或设备控制接口。所有写入保留操作者、时间、输入摘要和审批记录。

## 仓库当前实现

`src/torque_guard/integrations/feishu.py` 只构造字段预览，输出到 `outputs/feishu_records_preview.json`。它不读取凭证，也不发送请求，便于公开仓库安全展示。
