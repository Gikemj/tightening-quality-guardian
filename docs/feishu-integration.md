# 飞书协同接入设计与当前边界

## 能力状态

| 能力 | 当前状态 | 不能据此声称 |
|---|---|---|
| 多维表格字段映射 | 已实现风险主记录与任务记录的结构化载荷 | 已在企业表格中完成业务闭环 |
| 本地预览 | 默认模式，只写入 `outputs/feishu_records_preview.json` | 已发送飞书消息或创建真实任务 |
| 多维表格 live 客户端 | 已实现鉴权、风险表/任务表批量写入、超时、严格响应确认和鉴权安全重试；创建 POST 不自动重放；本地结果默认隔离到 `.local/live/` | 已在授权租户联调或达到生产可靠性 |
| 审批门禁 | live 方法先校验完整风险卡，再把强类型批准凭证逐字段核对到风险卡中的真实批准事件；状态机也限制审批前建任务 | 已接入飞书审批、企业人员目录或电子签名 |

## 目标流程

发现风险后，系统生成风险主记录和待审批任务。工程师确认后，才允许把风险和任务写入经授权的多维表格；现场验证通过、记录完整并再次满足授权条件后，才能结案和沉淀案例。

```text
风险草案 → 具名审批 → 风险主表/任务子表 → 现场验证 → 结案 → 案例回写
```

当前代码覆盖载荷构造、live 风险/任务写入和本地状态机，但没有把飞书审批、现场验证、结案及案例回写连接成一个真实企业租户闭环。

## 多维表格设计

### 风险主表

当前载荷包含：风险卡编号、工位、工具、紧固点、风险等级、风险评分、状态、证据数量、窗口开始/结束、批准人和批准依据。

企业联调还应增加：工厂/车间数据域、规则/知识/Prompt 版本、创建人与更新时间、审批记录 ID、结案时间和权限标签。

### 任务子表

当前任务载荷字段如下；其中“候选原因”始终表示待现场验证的假设，不是已确认根因：

| 多维表格字段 | 风险卡来源 | 合同与边界 |
|---|---|---|
| 风险卡编号 | `card_id` | 与风险主表关联 |
| 任务编号 | `recommended_actions[].action_id` | 单张风险卡内唯一 |
| 任务 | `title` | 非空任务标题 |
| 责任角色 | `owner_role` | 当前是角色，不冒充已分配企业用户 |
| 时限（分钟） | `due_minutes` | 正整数 |
| 需人工审批 | `approval_required` | 必须为 `true` |
| 验收依据 | `acceptance_criteria` | 完成任务所需的可核验记录 |
| 生成依据 | `why` | 说明为何需要该验证任务，不作根因确认 |
| 关联证据 | `evidence_ids` | 文本连接；每个 ID 必须存在于同一风险卡证据链 |
| 候选原因 | `candidate_causes` | 文本连接；每个名称必须匹配同一风险卡中的待验证候选原因 |
| 状态 | 预览/live 同步状态 | 部分成功或失败时禁止显示为可执行 |
| 批准人 | live 审批凭证 | 公开预览为空，不伪造企业身份 |

Python 风险卡会在序列化及发送前严格校验“生成依据”“关联证据”和“候选原因”。空列表、重复引用、未知证据或不存在的候选原因都会失败关闭；稳定监控卡仍不生成任务。

企业联调还应增加：企业用户 ID、实际责任人、附件、处理结论、验证证据 ID、超时升级、幂等键和最后同步状态。

### 知识案例表

建议字段为：失效模式、最终原因、验证方法、处置措施、效果验证、适用范围、来源风险卡、版本和批准人。

`FEISHU_CASE_TABLE_ID` 已作为可选配置预留，但当前客户端尚未实现案例表写入，不能把建议表结构表述为已落地能力。

## Aily / Agent 目标工具

企业试点可向 Aily 或其他受控 Agent 暴露白名单工具：

1. `read_recent_events`：按授权对象读取最近窗口；
2. `run_spc_checks`：返回规则命中和计算细节；
3. `retrieve_quality_subgraph`：返回带来源的有限子图；
4. `create_risk_draft`：生成草案，不直接发布；
5. `create_tasks_after_approval`：审批后写入多维表格；
6. `close_case`：核对验证与验收字段后结案并沉淀案例。

这些是目标工具合同，不是当前仓库中已经配置完成的 Aily 工具。当前 Agent 在本地执行读取、分析、结构化研判和工作流初始化，并由 [`AuditTrail`](../src/torque_guard/workflow.py) 记录真实调用边界。

## 当前代码路径

### 预览模式（默认）

```powershell
python -m torque_guard.cli `
  --input data/tightening_events_demo.csv `
  --knowledge knowledge `
  --point P03 `
  --feishu-mode preview
```

该模式只生成本地 JSON，不读取飞书凭证，不发送网络请求。

### live 模式（仅限授权测试环境）

live 客户端读取以下环境变量：

| 环境变量 | 用途 | 是否必需 |
|---|---|---|
| `FEISHU_APP_ID` | 企业自建应用 ID | 是 |
| `FEISHU_APP_SECRET` | 企业自建应用密钥 | 是 |
| `FEISHU_BITABLE_APP_TOKEN` | 多维表格应用 Token | 是 |
| `FEISHU_RISK_TABLE_ID` | 风险主表 ID | 是 |
| `FEISHU_TASK_TABLE_ID` | 任务子表 ID | 是 |
| `FEISHU_CASE_TABLE_ID` | 知识案例表 ID | 否，当前未写入 |
| `FEISHU_API_BASE` | API 基址 | 否，默认飞书开放平台 |

凭证只应由企业密钥管理或当前进程环境注入，不得写进命令历史、仓库、截图或日志。配置完整后，授权测试人员可显式运行：

客户端会拒绝非 HTTPS、带账号信息/查询参数/片段的 API 基址，也会拒绝在应用 Token 或表 ID 中出现路径字符；超时和重试次数必须是有效正数。这些检查用于降低误配置导致的凭证泄露或请求路径偏移风险，但不能替代企业出口控制和密钥轮换。

```powershell
python -m torque_guard.cli `
  --input data/tightening_events_demo.csv `
  --knowledge knowledge `
  --point P03 `
  --feishu-mode live `
  --approved-by "经授权的审批人标识" `
  --approval-note "经核验的审批依据"
```

live 模式未显式指定输出路径时，只会把风险卡和飞书载荷副本写入
`.local/live/risk_card.json` 与 `.local/live/feishu_records_preview.json`。该目录已被
`.gitignore` 忽略，因为文件可能包含批准人、批准依据、请求 ID、远端记录 ID 和错误详情。
不要把这些 live 文件复制到 `outputs/`、`docs/data/` 或提交到版本控制。若通过
`--output`、`--feishu-preview` 指定其他位置，应选择仓库外的受控私有目录，并按企业数据保留策略管理。

缺少任一必需配置、批准人或批准依据时，live 模式会失败关闭，而不是静默假装创建成功。公开仓库没有执行这条真实调用的授权条件。

## 已实现的网络行为

[`FeishuBitableClient`](../src/torque_guard/integrations/feishu.py) 当前会：

1. 使用应用 ID 与密钥获取 `tenant_access_token`；
2. 向风险表批量创建 1 条风险记录；
3. 向任务表批量创建风险卡中的任务记录；
4. 只对鉴权阶段明确可安全重试的传输失败执行有限重试；批量创建 POST 遇到未知结果时不自动重放，避免重复建单；
5. 要求成功响应顶层 `code=0`，鉴权响应包含非空字符串 `tenant_access_token`；批量写入的 `data.records` 数量必须与请求一致，每条记录必须有唯一 `record_id`；若响应同时返回 `fields`，还必须逐条匹配请求业务键；
6. 在发起网络请求前重新验证风险卡完整性，并要求批准凭证的事件 ID、动作、前后状态、批准人、依据和时间与 `card.workflow.events` 中的真实事件全部一致；
7. 返回 `sync_status`、请求 ID、已确认远端 ID、失败阶段和人工对账标记。

这些行为已通过注入式假传输测试验证请求结构，见 [`tests/test_feishu_live.py`](../tests/test_feishu_live.py)。测试没有访问飞书网络。

## 仍需解决的生产化缺口

- 风险表成功、任务表失败时可能形成部分写入；当前没有跨表事务或补偿流程；
- 创建 POST 不会自动重放，但人工重试或客户端重启后仍缺少企业级幂等键、远端查重与 outbox 对账；
- 本地代码会核对强类型工作流批准凭证、批准人和依据，但尚未与飞书审批记录、企业身份目录或电子签名核验；
- CLI 已协调本地 [`RiskCaseWorkflow`](../src/torque_guard/workflow.py) 与 live 客户端：先批准、成功写完风险/任务后再标记 `tasks_created`，部分失败不会越级；但完整状态事件仍未持久化到飞书，也未绑定飞书审批记录；
- 尚未实现超时升级、撤销、附件同步、结案和案例表写回；
- 尚未验证真实字段类型、必填规则、人员字段、表权限、限流和错误码；
- 尚未完成 Aily 应用、工具白名单、知识权限或真实调用；
- 尚未形成防篡改、可长期留存的企业审计日志。
