# 赛力斯设备闭环脱敏数据与项目对齐说明

这份说明回答两个问题：赛力斯设备场景闭环脱敏数据包在项目中承担什么作用，以及为什么公开演示没有把它当成真实产线数据来计算。

## 数据包的用途

数据包提供设备类别、设备实例、设备功能、失效模式和故障工单等对象及其字段关系。它适合做三件事：

1. 确定设备质量知识底座的对象类型和主键关系；
2. 检查工单能否沿“实例 → 类别 → 功能 → 失效模式”找到可用证据；
3. 把缺失关系转成补证任务，而不是让模型自行补齐。

汇总数字来自脱敏包的结构核对：625 个设备类别、9673 个设备实例、336 个设备功能、1287 个失效模式和 406 个故障工单。383 个工单能沿设备实例回到设备类别，71 个工单带有失效模式关联，62 个工单满足当前定义的类型一致结构闭环候选。完整数字和分母见 [`docs/data/seres-equipment-closure-summary.json`](data/seres-equipment-closure-summary.json)。

## 关系链如何服务本项目

赛题推荐关系链为：

```text
设备类别 → 设备实例 → 故障工单 → 失效模式 → 设备功能 → 设备类别
```

公开页面的“设备工单关系案卷”用三个 `CASE-DEMO-*` 合成案卷演示这条链上的三种情况：链路较完整、存在候选关联、需要先补齐字段。每个案卷都把直接事实、关联候选和信息缺口分开，任务草案包含责任角色、时限、验收依据和证据 ID。案卷不会把历史关联改写成根因，也不会创建真实飞书任务。

项目的主演示是总装关键拧紧工位 ST-FAS-07 / TQ-17 / P03。扭矩、角度、重试和标定信号来自独立的确定性合成时序，用于展示“规格内但过程正在变化”如何形成风险卡。赛题脱敏包与这组时序在代码和页面上分开标注，避免把结构参考误写成现场测量。

## 缺失字段的处理

数据包没有原始设备手册、维修手册和图纸。缺少 S/O/D、RPN、真实地点、品牌、型号、人员等字段时，页面保留缺失状态，并把后续动作写成“补证”或“人工核验”。系统不根据脱敏快照推断真实设备状态、真实故障概率、真实质量影响或赛力斯收益。

## 评委可核验路径

- 在线页面：打开“赛题数据基础”，查看规模、关系覆盖率和使用边界；
- 公开案卷：切换不同 `CASE-DEMO-*`，点击“重新核验关系”和“生成任务预览”；
- 管理员页面：进入“数据与知识”，查看同一份数据边界摘要；
- 仓库文件：查看本文件、`docs/data/seres-equipment-closure-summary.json`、`docs/data/round2_reports.json` 以及 `knowledge/ontology.json`。

这套展示证明的是数据合同、关系核验和工作流设计，不是企业生产系统已经接入或取得了现场效果。
